# Commercial Contracts Dashboard

Управленческий веб-дашборд коммерческих договоров на Google Apps Script. Данные читаются непосредственно из рабочей Google Таблицы и автоматически обновляются в интерфейсе.

## Что показывает дашборд

- **Pulse**: сводный KPI, приход, контрактация, подписанный портфель, статусы и квартальная динамика.
- **Результаты**: сравнение 2025 и 2026 годов, планы и факты по кварталам, накопительный прогресс.
- **Договоры**: подписанные договоры, opportunities и субсидии; поиск, фильтры, сортировка, CSV и ссылки на сохранённый срез.
- **Управленческий фокус**: сценарий прихода, контрактация, opportunities, состояние процесса и пять крупнейших активных остатков.
- **Контроль данных**: автоматические замечания с переходом к проблемной строке.
- **Режим доклада**, краткий текстовый отчёт и печатная версия для PDF.

Доступны тёмная, светлая и корпоративная темы. Ранее предложенная тёмно-зелёная тема намеренно исключена.

## Источники данных

Серверный слой читает листы:

- `Статус`;
- `Контрактация/закрытие 2026`.

Поддерживаются направления `Разработка ТС`, `Разработка ПОДД` и `Прочие договоры`. Фактические поступления определяются по зелёному цвету шрифта, прогнозные значения — по синему.

Итог контрактации 2025 ищется по структуре блока `2025 / Контр 1 кв. … / Итого`, а не по фиксированной ячейке. Вставка или удаление строк поэтому не должна ломать расчёт.

## Структура

| Файл | Назначение |
| --- | --- |
| `Code.gs` | Точка входа веб-приложения и HTML includes |
| `Data.gs` | Чтение таблицы, расчёты KPI, реестр и контроль качества |
| `SUMFONT.gs` | Надёжная сумма по цвету шрифта и автоматический пересчёт |
| `BRO.html` | Разметка интерфейса |
| `Styles.html` | Темы, адаптивная и печатная версии |
| `Assets.html` | Встроенные графические ресурсы |
| `Client.html` | Отрисовка, фильтры, отчёты и автообновление |
| `appsscript.json` | Манифест Google Apps Script |

## Первичная настройка

1. Откройте Apps Script именно из рабочей Google Таблицы.
2. Добавьте файлы проекта или выполните `clasp push` после настройки `.clasp.json`.
3. В свойствах скрипта создайте `SPREADSHEET_ID` со значением ID рабочей таблицы.
4. Один раз выполните `setupSUMFONT()` и подтвердите необходимые разрешения.
5. Выполните `checkSUMFONT()`: три именованных диапазона должны существовать, а активный триггер `SUMFONT_WATCH` должен быть один.
6. Выполните `testDashboardDataFull()` и убедитесь, что `contracting.unmatchedItems` пуст.
7. Выполните `clearDashboardCache()`, затем один раз `installDashboardTriggers()`.

## Проверка перед публикацией

```bash
npm test
```

После статической проверки откройте тестовую `/dev`-ссылку и проверьте:

- все три раздела и три цветовые темы;
- «Управленческий фокус» и «Контроль данных»;
- фильтры, ссылку на срез, CSV и краткий отчёт;
- режим доклада и «Печать / PDF»;
- автообновление и ручную кнопку «Обновить»;
- отображение на телефоне.

## Публикация без смены рабочей ссылки

Откройте **Развернуть → Управление развёртываниями**, выберите действующее веб-приложение, нажмите значок карандаша, выберите **Новая версия** и разверните её.

Не создавайте новое развёртывание, если необходимо сохранить текущую `/exec`-ссылку.

## Обновление данных

- клиент запрашивает данные при открытии и далее раз в 60 секунд;
- при возвращении на вкладку после паузы выполняется дополнительная проверка;
- серверный кэш действует 30 секунд;
- изменения структуры или содержимого таблицы сбрасывают кэш установленными триггерами.
